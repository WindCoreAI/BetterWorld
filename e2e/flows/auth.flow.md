## Test Scenarios

### Scenario 1: Human Registration via Email/Password

**Pages**: /auth/human/register -> /auth/human/verify
**Auth Required**: No
**Prerequisites**: None

**Steps**:
1. Navigate to `/auth/human/register`
2. Verify page heading "Join BetterWorld" is visible
3. Verify OAuth buttons are present: "Continue with Google", "Continue with GitHub"
4. Fill form: displayName="E2E Test User", email="e2e-{uniqueId}@test.com", password="TestPass123!"
5. Click "Create Account" button
6. Expect redirect to `/auth/human/verify?email=e2e-...@test.com`
7. Verify heading "Verify Your Email" is visible
8. Verify 6 digit input boxes are present

**Expected Outcomes**:
- Page contains heading "Join BetterWorld"
- POST /api/v1/human-auth/register returns {ok: true}
- Redirect to verification page with email query param
- Verification page renders 6 input boxes for code entry

**API Calls Involved**:
- POST /api/v1/human-auth/register { email, password, displayName } -> { ok: true, data: { humanId, email } }

**Selectors**:
- Heading: `text=Join BetterWorld`
- Display name input: `input[type="text"][placeholder="Your name"]`
- Email input: `input[type="email"][placeholder="you@example.com"]`
- Password input: `input[type="password"][placeholder*="8+ characters"]`
- Submit button: `text=Create Account`
- OAuth Google: `text=Continue with Google`
- OAuth GitHub: `text=Continue with GitHub`
- Login link: `text=Already have an account`

### Scenario 2: Human Login with Valid Credentials

**Pages**: /auth/human/login -> /dashboard
**Auth Required**: No (login page) -> Yes (dashboard)
**Prerequisites**: Registered human with verified email (use `registerAndLoginHuman` helper or DB bypass)

**Steps**:
1. Navigate to `/auth/human/login`
2. Verify page heading "Welcome Back" is visible
3. Fill form: email="{registered_email}", password="{password}"
4. Click "Log In" button
5. Expect redirect to `/dashboard`
6. Verify dashboard heading "Welcome back" is visible
7. Verify tokens stored in localStorage: `bw_human_access_token`, `bw_human_refresh_token`

**Expected Outcomes**:
- POST /api/v1/human-auth/login returns {ok: true, data: { accessToken, refreshToken, human }}
- Redirect to /dashboard
- Tokens stored in localStorage
- Dashboard loads with user's display name

**API Calls Involved**:
- POST /api/v1/human-auth/login { email, password } -> { ok: true, data: { accessToken, refreshToken, human: { id, email, displayName } } }
- GET /api/v1/dashboard (auto-called by useHumanAuth on mount)

**Selectors**:
- Heading: `text=Welcome Back`
- Email input: `input[type="email"][placeholder="you@example.com"]`
- Password input: `input[type="password"][placeholder="Your password"]`
- Submit button: `text=Log In`
- Dashboard heading: `text=Welcome back`

### Scenario 6: Logout Clears Tokens

**Pages**: /dashboard -> /auth/human/login (or /)
**Auth Required**: Yes
**Prerequisites**: Authenticated human session

**Steps**:
1. Authenticate in browser via `authenticateInBrowser`
2. Navigate to `/dashboard`
3. Verify dashboard loads with user name visible
4. Click logout button in navigation (user display name area)
5. Verify tokens cleared from localStorage
6. Verify redirected away from dashboard

**Expected Outcomes**:
- POST /api/v1/human-auth/logout called
- localStorage keys `bw_human_access_token` and `bw_human_refresh_token` removed
- Navigation shows Login/Join buttons instead of user name
- Cannot access /dashboard without re-authenticating

**API Calls Involved**:
- POST /api/v1/human-auth/logout (with bearer token)

**Selectors**:
- User name in nav: Navigation displays `displayName`
- Logout button: `text=Logout`
- Login link (after logout): `text=Login` or `a[href="/auth/human/login"]`
- Join button (after logout): `text=Join` or `a[href="/auth/human/register"]`
