# Admin Flow

> Generated by /ux-flows on 2026-02-17

## Setup Requirements

- [ ] API server running (port 4000)
- [ ] Web server running (port 3000)
- [ ] PostgreSQL with betterworld database
- [ ] Redis running
- [ ] Admin JWT token (human with role="admin")
- [ ] Note: Admin tests require special setup — admin credentials may need to be created via DB seeding

## Test Scenarios

### Scenario 1: Admin Dashboard Loads (Requires Admin Role)

**Pages**: /admin
**Auth Required**: Yes (admin JWT token validated in layout)
**Prerequisites**: Valid admin JWT token set in localStorage as `bw_admin_token`

**Steps**:
1. Set admin token in localStorage: `bw_admin_token`
2. Navigate to `/admin`
3. Verify admin layout renders with sidebar navigation
4. Verify heading "Admin Dashboard" is visible
5. Verify Pending Reviews count card
6. Verify Total Flagged count card
7. Verify System Status health card
8. Verify Quick Actions section: "Review Flagged Content" and "Fraud Review Queue" buttons

**Expected Outcomes**:
- Admin panel loads with dashboard content
- Admin nav shows links: Admin, Flagged Content, Fraud Review, Shadow Mode, Production Shift, City Dashboards
- Quick action buttons link to respective admin pages

**API Calls Involved**:
- GET /api/v1/admin/flagged?status=pending (count)
- Various admin health check calls

**Selectors**:
- Heading: `text=Admin Dashboard`
- Pending reviews: Count card
- Total flagged: Count card
- System status: Health indicator card
- Review flagged button: `text=Review Flagged Content`
- Fraud review button: `text=Fraud Review Queue`
- Admin nav links: Links in admin sidebar

4. Verify admin content is NOT rendered

**Expected Outcomes**:

- No admin functionality accessible without valid admin JWT

**API Calls Involved**:

### Scenario 3: Flagged Content Queue

**Pages**: /admin/flagged
**Auth Required**: Yes (admin)
**Prerequisites**: Admin token, some flagged content in the system

**Steps**:
1. Set admin token and navigate to `/admin/flagged`
2. Verify heading "Flagged Content Review" is visible
3. Verify status filter tabs (All, Pending, Approved, Rejected)
4. Verify flagged content card list renders
5. Click on "Pending" tab
6. Verify list filters to pending items
7. Click on a flagged content card
8. Expect navigation to `/admin/flagged/{id}` detail page
9. Verify detail page shows: Agent Context, Submitted Content, Layer A result, Layer B result
10. Verify Review Decision Form (approve/reject + notes)

**Expected Outcomes**:
- Flagged content list loads with filter tabs
- Individual items link to detail review page
- Detail shows full guardrail evaluation pipeline results
- Review form allows approve/reject with notes

**API Calls Involved**:
- GET /api/v1/admin/flagged?status=pending -> { ok: true, data: { items: [...], cursor } }
- GET /api/v1/admin/flagged/:id -> { ok: true, data: { item, evaluation } }
- PATCH /api/v1/admin/flagged/:id { decision, notes } -> { ok: true }

**Selectors**:
- Heading: `text=Flagged Content Review`
- Status tabs: Buttons/tabs for All, Pending, Approved, Rejected
- Content cards: FlaggedContentCard components
- Load more: `text=Load More`
- Detail page heading: `text=Review Flagged Content`
- Agent context card: Card showing trust tier, content type, agent ID
- Layer A result: Card showing pass/fail and patterns
- Layer B result: Card showing alignment score, dimensions
- Review form: ReviewDecisionForm with approve/reject buttons and notes textarea

### Scenario 5: Shadow Mode Dashboard (Admin)

**Pages**: /admin/shadow
**Auth Required**: Yes (admin)

**Steps**:
1. Set admin token and navigate to `/admin/shadow`
2. Verify heading "Shadow Mode Dashboard"
3. Verify Overall Agreement Rate (big percentage)
4. Verify disagreement breakdown (Peer Approve Layer B Reject / Peer Reject Layer B Approve)

6. Verify Agreement by Submission Type chart (AgreementChart)
7. Verify Latency Histogram (LatencyHistogram)

**Selectors**:

- Type chart: AgreementChart component with "Agreement by Submission Type"
