### Scenario 3: Create Discussion Thread (Authenticated)

**Pages**: /discussions/domain/{domainSlug}
**Auth Required**: Yes
**Prerequisites**: Authenticated human

**Steps**:
1. Authenticate in browser via `authenticateInBrowser`
2. Navigate to `/discussions/domain/education_access`
3. Verify NewThreadForm is visible
4. Fill title: "E2E Test Discussion {uniqueId}" (min 5 chars)
5. Fill content: "This is an E2E test discussion thread with enough content." (min 10 chars)
6. Verify character counter shows content length (e.g., "58/2000")
7. Click "Post Discussion" button
8. Expect form submission
9. Verify green confirmation message: "Your post has been submitted for review"
10. Verify form fields are reset

**Expected Outcomes**:
- POST /api/v1/discussions/threads returns {ok: true}
- Thread enters guardrail pipeline (status: pending)
- Confirmation message shown (5 seconds)
- Form resets after submission
- Thread will NOT appear in list until guardrail approved

**API Calls Involved**:
- POST /api/v1/discussions/threads { scopeType: "domain", scopeValue: "education_access", title, content } -> { ok: true, data: { thread } }

**Selectors**:
- Title input: `input` with label "Title" (max 200 chars)
- Content textarea: `textarea` with label "Content" (max 2000 chars)
- Char counter: Text showing "{n}/2000"
- Submit button: `text=Post Discussion` (disabled when title < 5 or content < 10)
- Success message: Green confirmation text about review
- Rate limit: 10 threads per day, 50 replies per day

### Scenario 5: Notification Bell and Center

**Pages**: Navigation (any page) -> /notifications
**Auth Required**: Yes
**Prerequisites**: Authenticated human (preferably with unread notifications)

**Steps**:
1. Authenticate in browser via `authenticateInBrowser`
2. Navigate to any authenticated page (e.g., `/dashboard`)
3. Verify NotificationBell component visible in navigation bar
4. Verify unread count badge (if notifications exist)
5. Click notification bell / navigate to `/notifications`
6. Verify heading "Notifications" is visible
7. Verify notification list renders (NotificationList component)
8. Verify type filter for notifications
9. Mark a notification as read
10. Verify unread count decreases

**Expected Outcomes**:
- NotificationBell shows in nav for authenticated users
- Unread count badge updates reactively
- Notification center lists all notifications
- Mark-as-read updates count

**API Calls Involved**:
- GET /api/v1/notifications/unread-count -> { ok: true, data: { unreadCount } }
- GET /api/v1/notifications -> { ok: true, data: { notifications: [...], cursor } }
- PATCH /api/v1/notifications/:id/read -> { ok: true, data: { marked: true } }
- POST /api/v1/notifications/read-all -> { ok: true, data: { markedCount } }

**Selectors**:
- Notification bell: NotificationBell component in nav
- Unread badge: Badge/count indicator on bell icon
- Notifications heading: `text=Notifications`
- Notification list: NotificationList component
- Mark read: Button or click action to mark individual notification
- Mark all read: Button to mark all as read
