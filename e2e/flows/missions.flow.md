## Test Scenarios

### Scenario 1: Browse Mission Marketplace with Filters

**Pages**: /missions
**Auth Required**: Yes (onboarding guard redirects to /onboarding if not completed)
**Prerequisites**: Authenticated human with completed onboarding, missions exist

**Steps**:
1. Authenticate in browser via `authenticateInBrowser`
2. Navigate to `/missions`
3. Verify heading "Mission Marketplace" is visible
4. Verify List/Map toggle buttons visible
5. Verify sidebar filters visible (MissionFilters component)
6. Verify mission cards list renders
7. Apply domain filter (e.g., "Education Access")
8. Verify filtered results
9. Apply difficulty filter
10. Verify "Load More" for pagination
11. Click "Retry" button if error occurs

**Expected Outcomes**:
- Page loads with "Mission Marketplace" heading
- GET /api/v1/missions returns active missions
- Filters narrow results by domain, difficulty, skills, reward, duration, geo
- Pagination via "Load More" button

**API Calls Involved**:
- GET /api/v1/missions?limit=12 -> { ok: true, data: { missions: [...], cursor } }
- GET /api/v1/missions?domain=education_access (filtered)
- GET /api/v1/missions?difficulty=easy (filtered)

**Selectors**:
- Heading: `text=Mission Marketplace`
- List toggle: Toggle/button for list view
- Map toggle: Toggle/button for map view
- Filters sidebar: MissionFilters component with domain, difficulty, skills, reward, duration selects
- Mission cards: List of MissionCard components
- Load more: `text=Load More`
- Retry: `text=Retry`

### Scenario 4: Mission Claiming Flow

**Pages**: /missions/[id]
**Auth Required**: Yes
**Prerequisites**: Authenticated human, active mission with available slots, human has fewer than 3 active claims

**Steps**:
1. Authenticate in browser
2. Navigate to a specific mission detail: `/missions/:id`
3. Verify "Claim Mission" button is visible and enabled
4. Click "Claim Mission"
5. Expect claiming API call
6. Verify button state changes (e.g., "Claimed" or claim status section)
7. Verify "Submit Evidence" link appears after claiming
8. Verify exact location revealed on map after claiming

**Expected Outcomes**:
- POST /api/v1/missions/:id/claim returns {ok: true, data: { claim }}
- Atomic claim with SELECT FOR UPDATE SKIP LOCKED
- Max 3 active claims enforced (error if exceeded)
- Location details revealed after successful claim
- 7-day deadline starts on claim

**API Calls Involved**:
- POST /api/v1/missions/:id/claim -> { ok: true, data: { claim: { id, humanId, missionId, status, deadline } } }
- GET /api/v1/missions/:id (refresh with full location)

**Selectors**:
- Claim button: `text=Claim Mission` (MissionClaimButton component)
- Claiming state: `text=Claiming...`
- Claimed state: Claim status section with deadline
- Submit evidence link: Link to `/missions/:id/submit`
- Already claimed: `text=Already Claimed`
- Fully claimed: `text=Fully Claimed`
