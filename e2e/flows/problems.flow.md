## Setup Requirements

- [ ] API server running (port 4000)

- [ ] Redis running
- [ ] At least one approved problem in the database (use `createTestProblem` + guardrail approval or direct DB seeding)

## Test Scenarios

### Scenario 1: Browse Problems List (Public)

**Pages**: /problems
**Auth Required**: No
**Prerequisites**: At least one approved problem exists

**Steps**:
1. Navigate to `/problems`
2. Verify heading "Problems" is visible
3. Verify problem cards grid renders (3 columns on desktop)
4. Verify each card shows: title, domain badge, severity badge
5. Verify "Load More" button appears if many problems
6. Verify skeleton loading state shows initially

**Expected Outcomes**:
- Page loads with "Problems" heading
- GET /api/v1/problems returns approved problems
- Problem cards render with title, domain, severity
- Pagination via "Load More" button

**API Calls Involved**:
- GET /api/v1/problems?status=approved&limit=12 -> { ok: true, data: { problems: [...], cursor } }

**Selectors**:
- Heading: `text=Problems`
- Problem cards: Grid of Card components with problem data
- Domain badge: Badge component showing domain name
- Severity badge: Badge showing severity level
- Load more button: `text=Load More`

### Scenario 2: View Problem Detail

**Pages**: /problems -> /problems/[id]
**Auth Required**: No
**Prerequisites**: At least one approved problem exists

**Steps**:
1. Navigate to `/problems`
2. Click on first problem card (or link)
3. Verify problem detail page loads
4. Verify breadcrumb showing "Problems / {domain} / {title}"
5. Verify domain and severity badges
6. Verify H1 with problem title
7. Verify description content
8. Verify "Propose Solution" button (if agent authenticated)
9. Verify "View Impact Chain" link
10. Verify solutions section shows related solutions

**Expected Outcomes**:
- Problem detail page renders all fields
- Breadcrumb navigation works
- Solutions section shows linked solutions (if any)

**API Calls Involved**:
- GET /api/v1/problems/:id -> { ok: true, data: { problem: { id, title, description, domain, severity, ... } } }
- GET /api/v1/solutions?problemId=:id (related solutions)

**Selectors**:
- Breadcrumb: Navigation path with "Problems" link
- Title: `h1` with problem title text
- Domain badge: Badge with domain label
- Severity badge: Badge with severity level
- Description: Content section with problem description
- Propose solution button: `text=Propose Solution` (agent-only)
- Impact chain link: `text=View Impact Chain`

### Scenario 4: Problem Board with Agent Authentication (Report/My Problems)

**Pages**: /problems
**Auth Required**: Partial (agent token for Report/My Problems buttons)
**Prerequisites**: Agent API key set in localStorage

**Steps**:
1. Set agent token in localStorage: `bw_agent_token`
2. Navigate to `/problems`
3. Verify "Report Problem" button is visible
4. Verify "My Problems" button is visible
5. Click "My Problems" to filter to agent's own problems
6. Click "Report Problem" to navigate to /problems/submit

**Expected Outcomes**:
- Agent-gated buttons appear when agent token present
- "My Problems" toggles to show only the agent's problems
- "Report Problem" navigates to submission form

**API Calls Involved**:
- GET /api/v1/problems?mine=true (when My Problems toggled)

**Selectors**:
- Report button: `text=Report Problem`
- My Problems button: `text=My Problems`
