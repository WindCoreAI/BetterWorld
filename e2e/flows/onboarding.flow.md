# Onboarding Flow

> Generated by /ux-flows on 2026-02-17

## Setup Requirements

- [ ] API server running (port 4000)
- [ ] Web server running (port 3000)
- [ ] PostgreSQL with betterworld database
- [ ] Redis running
- [ ] Registered human with verified email (via `registerAndLoginHuman` helper)
- [ ] Human must NOT have completed orientation yet

## Test Scenarios

### Scenario 1: Orientation Wizard Completion (5 Steps)

**Pages**: /onboarding
**Auth Required**: Yes (redirects to /auth/human/login if unauthenticated)
**Prerequisites**: Authenticated human who has NOT completed orientation

**Steps**:
1. Authenticate in browser via `authenticateInBrowser`
2. Navigate to `/onboarding`
3. Verify 5-step progress indicator visible (Constitution, Domains, Missions, Evidence, Tokens)
4. **Step 1 - Constitution**: Verify constitution content visible, click "Next" or "Continue"
5. **Step 2 - Domains**: Verify domain selection content, click "Next"
6. **Step 3 - Missions**: Verify missions explanation content, click "Next"
7. **Step 4 - Evidence**: Verify evidence explanation content, click "Next"
8. **Step 5 - Tokens**: Verify token explanation content, click "Claim Tokens" button
9. Expect orientation reward API call
10. Expect redirect to `/dashboard` after completion

**Expected Outcomes**:
- 5-step progress bar renders with step names
- Each step content renders correctly
- POST /api/v1/tokens/orientation-reward returns {ok: true} with 10-token grant
- Redirect to /dashboard after final step
- Subsequent visits to /onboarding redirect to /dashboard (already completed)

**API Calls Involved**:
- GET /api/v1/dashboard (auth check)
- GET /api/v1/profile (check orientation status)
- POST /api/v1/tokens/orientation-reward { } -> { ok: true, data: { transaction } }

**Selectors**:
- Progress steps: Step indicators showing 1-5
- Step 1 heading: Content about BetterWorld constitution
- Step 2 heading: Content about domains
- Step 3 heading: Content about missions
- Step 4 heading: Content about evidence
- Step 5 heading: Content about tokens
- Claim button: `text=Claim Tokens`
- Next button: `text=Next` or `text=Continue`

### Scenario 3: Profile Creation

**Pages**: /auth/human/profile
**Auth Required**: Yes (redirects to /auth/human/login if unauthenticated)
**Prerequisites**: Authenticated human without a profile

**Steps**:
1. Authenticate in browser via `authenticateInBrowser`
2. Navigate to `/auth/human/profile`
3. Verify heading "Complete Your Profile" visible
4. Add skills: type "javascript" in skills input, select from suggestions
5. Select country from dropdown (e.g., "United States")
6. Select city from dropdown (e.g., "Portland")
7. Toggle languages: click "English" button
8. Enter bio text in textarea (max 500 chars)
9. Toggle availability days: click "Mon", "Wed", "Fri"
10. Click "Create Profile" or "Save" button
11. Expect profile creation success

**Expected Outcomes**:
- POST /api/v1/profile returns {ok: true, data: { profile }}
- Profile completeness score calculated
- Geocoding triggered for city/country (Nominatim)
- Redirect or success message after creation

**API Calls Involved**:
- GET /api/v1/profile (check if profile exists)
- POST /api/v1/profile { skills, country, city, languages, bio, availability } -> { ok: true, data: { profile, completenessScore } }

**Selectors**:
- Heading: `text=Complete Your Profile` or `text=Edit Your Profile`
- Skills input: Autocomplete input for skills
- Country dropdown: Combobox for country selection
- City dropdown: Combobox for city selection
- Language buttons: Toggle buttons for 15 languages (e.g., `text=English`)
- Bio textarea: `textarea` with 500 char max
- Availability days: Toggle buttons (Mon-Sun)
- Submit button: `text=Create Profile` or `text=Save`
