## Test Scenarios

### Scenario 1: Full New User Flow (Register → Verify → Profile → Onboarding → Dashboard)

**Pages**: /auth/human/register → /auth/human/verify → /auth/human/profile → /onboarding → /dashboard
**Auth Required**: No (starts unauthenticated)
**Prerequisites**: Clean database, no existing user

**Steps**:
1. Navigate to `/auth/human/register`
2. Fill Display Name, Email, Password
3. Click "Create Account"
4. Expect redirect to `/auth/human/verify?email=...`
5. Enter 6-digit verification code (dev: check API logs or DB `verification_tokens` table)
6. Expect redirect to `/auth/human/profile` after successful verification
7. Fill profile: skills, country, city, languages
8. Click "Create Profile & Continue"
9. Expect hard navigation to `/onboarding` (window.location.href)
10. Complete 5 orientation steps (Constitution → Domains → Missions → Evidence → Tokens)
11. Click "Claim Tokens" on Step 5
12. Expect hard navigation to `/dashboard` after 2s delay

**Expected Outcomes**:
- POST /api/v1/human-auth/register returns 201
- POST /api/v1/human-auth/verify-email sets tokens in localStorage
- POST /api/v1/profile creates profile
- POST /api/v1/tokens/orientation-reward grants 10 tokens
- Dashboard loads with user data, no "profile not found" errors
- No stale cache issues (hard navigation between stages)

**API Calls Involved**:
- POST /api/v1/human-auth/register { email, password, displayName }
- POST /api/v1/human-auth/verify-email { email, code }
- GET /api/v1/profile (returns null for new user)
- POST /api/v1/profile { skills, country, city, languages, ... }
- GET /api/v1/profile (onboarding checks orientationCompletedAt)
- POST /api/v1/tokens/orientation-reward
- GET /api/v1/dashboard

### Scenario 9: Stale Token After Database Reset

**Pages**: /dashboard → /auth/human/login
**Auth Required**: Yes (stale token)
**Prerequisites**: Old JWT in localStorage, database wiped/reset

**Steps**:
1. Set stale auth tokens in localStorage (valid JWT signature, but user doesn't exist in DB)
2. Navigate to `/dashboard`
3. Expect `useHumanAuth` to call GET /api/v1/dashboard → 401 "User not found"
4. Expect `humanFetch` to attempt token refresh → refresh also fails (user gone)
5. Expect tokens cleared from localStorage (`clearHumanTokens()`)
6. Expect `useHumanAuth` sets user to null
7. Expect dashboard page redirects to `/auth/human/login`

**Expected Outcomes**:
- Stale JWT triggers 401 from API
- Token refresh fails → tokens cleared
- User is redirected to login, not stuck on broken dashboard
- No "profile not found" error shown

**API Calls Involved**:
- GET /api/v1/dashboard → 401 (user not found)
- POST /api/v1/human-auth/refresh → fails (user not found)

**API Calls Involved**:
- POST /api/v1/human-auth/oauth/exchange { code }
- GET /api/v1/dashboard (via useHumanAuth checkAuth)

## Navigation Summary

```
Register → Verify Email → Profile Creation → Onboarding (5 steps) → Dashboard
                                    ↑                                      |
                                    |______________________________________|
                                    (guard: no profile → /auth/human/profile)

Login ──→ check profile ──→ no profile? ──→ /auth/human/profile
                        ├──→ no orientation? ──→ /onboarding
                        └──→ complete? ──→ /dashboard

Stale token ──→ 401 ──→ refresh fails ──→ clear tokens ──→ /auth/human/login
```

## Key Implementation Details

- **Hard navigation**: Profile → Onboarding → Dashboard transitions use `window.location.href` (not `router.push`) to ensure fresh state and avoid stale `useOnboardingGuard` cache
- **Onboarding guard**: Returns `redirectTo` field — `/auth/human/profile` (no profile) or `/onboarding` (no orientation)
- **Rate limits**: Auth endpoints have strict rate limits (register: 3/5min, login: 20/5min). Flush `auth:rl:*` Redis keys in test setup
- **Token cleanup**: `humanFetch` automatically clears tokens when 401 + refresh fails
