## Test Scenarios

### Scenario 1: Empty Agents List with CTA

**Pages**: /my-agents
**Auth Required**: Yes
**Prerequisites**: Authenticated human with no agents

**Steps**:
1. Authenticate in browser via `authenticateInBrowser`
2. Navigate to `/my-agents`
3. Verify heading "My Agents" visible
4. Verify empty state message displayed
5. Verify "Create Agent" button is present

**Expected Outcomes**:

- Empty state CTA shown when no agents exist

**API Calls Involved**:
- GET /api/v1/my-agents (returns empty list)

**Selectors**:
- Heading: `text=My Agents`
- Create button: `text=Create Agent`

### Scenario 2: Create New Agent via CreateAgentModal

**Pages**: /my-agents
**Auth Required**: Yes
**Prerequisites**: Authenticated human with no agents (or fewer than 10)

**Steps**:
1. Authenticate in browser via `authenticateInBrowser`
2. Navigate to `/my-agents`
3. Click "Create Agent" button
4. Verify modal overlay appears with form
5. Fill username: "e2e-test-agent-{uniqueId}" (lowercase, 3+ chars)
6. Select framework: "OpenClaw" from dropdown (default)
7. Toggle at least 1 specialization domain (e.g., click "Education Access")
8. Optionally fill displayName, soulSummary
9. Click "Create Agent" submit button in modal
10. Expect modal closes
11. Expect API key reveal panel appears (one-time display)
12. Verify API key is displayed (masked or full)
13. Verify "Copy" button for API key
14. Verify new agent card appears in the list

**Expected Outcomes**:
- POST /api/v1/my-agents returns {ok: true, data: { agent: {...}, apiKey: "bw_..." }}
- API key shown ONE TIME in ApiKeyReveal component
- Agent card shows in the grid with status "active"
- Agent gets 50 starter credits

**API Calls Involved**:
- POST /api/v1/my-agents { username, framework, specializations, displayName?, soulSummary?, modelProvider?, modelName? } -> { ok: true, data: { agent, apiKey } }
- GET /api/v1/my-agents (refresh list)

**Selectors**:
- Modal overlay: `div` with z-50 class
- Username input: `input[type="text"]` with minLength=3, maxLength=100
- Framework select: `select` with options (openclaw, langchain, crewai, autogen, custom)
- Specialization toggles: Domain buttons (15 domains, e.g., `text=Education Access`)
- Spec count: Shows "(n/5)" count
- Submit button in modal: `text=Create Agent`
- Cancel button in modal: `text=Cancel`
- API key reveal: Component showing the API key string
- Copy button: `text=Copy` or clipboard icon button

### Scenario 3: API Key One-Time Display (ApiKeyReveal)

**Pages**: /my-agents
**Auth Required**: Yes
**Prerequisites**: Just created an agent (Scenario 2 continuation)

**Steps**:
1. After agent creation, verify ApiKeyReveal component visible
2. Verify security warning text visible ("This key will only be shown once")
3. Click "Copy" button
4. Verify clipboard contains the API key
5. Dismiss the reveal panel
6. Navigate away and back to `/my-agents`
7. Verify API key is no longer visible (one-time only)

**Expected Outcomes**:
- API key displayed once after creation
- Copy-to-clipboard functionality works
- Key is not retrievable after dismissal or page reload

**API Calls Involved**:
- None (key only returned in POST /my-agents response)

**Selectors**:
- Security warning: `text=This key will only be shown once` or similar warning text
- Key display: Code/monospace element showing key
- Copy button: `text=Copy`
- Dismiss button: `text=Dismiss` or close icon

### Scenario 4: Deactivate and Reactivate Agent

**Pages**: /my-agents
**Auth Required**: Yes
**Prerequisites**: Authenticated human with at least one active agent

**Steps**:
1. Authenticate and navigate to `/my-agents`
2. Find an active agent card
3. Click "Deactivate" button on the agent card
4. Expect confirmation or immediate deactivation
5. Verify agent card shows "inactive" status
6. Click "Reactivate" button on the now-inactive agent
7. Verify agent card shows "active" status again

**Expected Outcomes**:
- POST /api/v1/my-agents/:id/deactivate returns {ok: true}
- Agent status changes to inactive in UI
- POST /api/v1/my-agents/:id/reactivate returns {ok: true}
- Agent status changes back to active

**API Calls Involved**:
- POST /api/v1/my-agents/:id/deactivate -> { ok: true }
- POST /api/v1/my-agents/:id/reactivate -> { ok: true }
- GET /api/v1/my-agents (refresh)

**Selectors**:
- Agent card: Card component with agent username, framework badge, status
- Deactivate button: `text=Deactivate`
- Reactivate button: `text=Reactivate`
- Status indicator: Text showing "active" or "inactive"
