### Scenario 2: Authenticated Pages Redirect When Not Authenticated

**Pages**: Protected pages
**Auth Required**: Yes (should redirect to login)
**Prerequisites**: None (unauthenticated state)

**Steps**:
1. Clear all localStorage tokens
2. Navigate to each protected page and verify redirect to login:
   - `/dashboard` — redirects to `/auth/human/login`
   - `/onboarding` — redirects to `/auth/human/login`
   - `/notifications` — redirects to `/auth/human/login`
   - `/dashboard/network` — redirects to `/auth/human/login`
   - `/auth/human/profile` — redirects to `/auth/human/login`
3. Navigate to pages with onboarding guard (requires auth + completed onboarding):
   - `/missions` — redirects to `/auth/human/login` or `/onboarding`
   - `/evidence-reviews` — redirects to `/onboarding` or shows error
   - `/disputes` — redirects to `/onboarding`
4. Navigate to `/my-agents` — shows login CTA (does not hard redirect)

**Expected Outcomes**:
- All protected pages redirect unauthenticated users to login
- Onboarding-guarded pages redirect to /onboarding if auth present but onboarding incomplete
- No protected content visible without authentication

**API Calls Involved**:
- None (client-side redirect logic in useHumanAuth and useOnboardingGuard)

**Selectors**:
- Login page heading: `text=Welcome Back`
- Onboarding page: Step indicators
